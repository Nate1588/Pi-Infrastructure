🚨 Pi Infrastructure Recovery Procedures

When to Use: After Pi crashes, reboots, or when .home domains redirect to wrong services

🔧 Quick Recovery (Most Common)

1. Automated Recovery Script

~/pi-infrastructure/scripts/post-crash-recovery.sh

This script will automatically restart nginx-proxy and test all key services.

2. Manual Recovery Steps

sudo docker restart nginx-proxy
sleep 5
curl -I http://grafana.home # Test service routing

🧹 Browser Cache Clearing

Problem: Browser shows wrong service (e.g., grafana.home shows NextCloud instead of Grafana)

Google Chrome

  • Method 1: Open DevTools (F12) → Right-click refresh → "Empty Cache and Hard Reload"
  • Method 2: Settings → Privacy → Clear browsing data → Check "Cached images and files" → Clear data
  • Method 3: Use Incognito window to test if cache is the issue

Firefox

  • Method 1: Ctrl+Shift+R (Windows/Linux) or Cmd+Shift+R (Mac) for hard refresh
  • Method 2: Settings → Privacy & Security → Clear Data → Check "Cached Web Content" → Clear Now
  • Method 3: Use Private window to test if cache is the issue

Safari

  • Method 1: Develop menu → Empty Caches (enable Develop menu in Preferences)
  • Method 2: Safari → Preferences → Privacy → Manage Website Data → Remove All
  • Method 3: Cmd+Shift+R for hard refresh

🔍 Troubleshooting Steps

1. Check Container Status

sudo docker ps --format "table {{.Names}}\t{{.Status}}\t{{.Ports}}"

2. Check nginx-proxy Logs

sudo docker logs nginx-proxy --tail 20

Look for "connection refused" errors indicating services aren't reachable.

3. Test DNS Resolution

nslookup grafana.home
dig @192.168.68.170 grafana.home

4. Test Direct Service Access

curl -I http://192.168.68.170:3000 # Direct Grafana
curl -I http://192.168.68.170:8080 # Direct Pi-hole
curl -I http://192.168.68.170:9000 # Direct Portainer

🛡️ Why This Happens

  • Container IP changes: After crashes, Docker assigns new internal IPs
  • nginx-proxy caching: Cached old container locations before they restarted
  • Browser caching: Cached incorrect redirects during the outage
  • Service startup order: nginx-proxy started before other services were ready
Prevention: The nginx configuration now prevents browser caching of error responses, making future recoveries faster.
